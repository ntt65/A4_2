# Rule-based NLP Pipeline (Python 3.11)

Python 표준 라이브러리만으로 이메일·전화번호·날짜·금액·URL을 추출·정규화하고, 사전과 규칙으로 문장 감성을 분석한다. 필수 미션 결과와 재현 방법을 이 문서에서 바로 확인할 수 있다.

## 설치와 실행

Python 3.11과 [uv](https://docs.astral.sh/uv/)를 사용한다. 외부 Python 패키지는 없으며 `requirements.txt`는 빈 의존성 목록이다.

```shell
uv venv --no-python-downloads .venv
uv pip sync --python .venv --allow-empty-requirements requirements.txt
uv run --python .venv python -B -X utf8 main.py --text "문의는 USER@EXAMPLE.COM, 연락처 010 1234 5678, 서비스는 정말 좋다"
uv run --python .venv python -B -X utf8 main.py --evaluate-all
uv run --python .venv python -B -X utf8 main.py --compare-sentiment
```

uv 없이 실행할 때는 표준 라이브러리만 필요한 현재 구성에서 다음 대체 절차를 사용할 수 있다.

```shell
python -m venv .venv
.venv/bin/python -B -X utf8 main.py --evaluate-all
```

Windows에서는 마지막 명령의 Python 경로를 `.venv\Scripts\python.exe`로 바꾼다.

평가 대상은 macOS·Python 3.11이고, 기록된 필수 미션 측정은 Windows 10·CPython 3.11.4에서 수행했다. 캐시 접근이 제한된 환경에서는 uv 명령에 `--no-cache`를 추가한다. `--evaluate-ie`와 `--evaluate-sentiment`로 평가를 나눌 수 있다.

## 필수 정보 추출

`src.extractor.extract_information(text)`가 다섯 종류를 한 번에 반환한다. 결과는 원문 등장 순으로 정렬하고 중복을 제거한다.

| 대상 | 지원 표기 예 | 표준 출력 |
|---|---|---|
| 이메일 | `user@example.com`, 대문자 도메인, `+tag`, 하위 도메인 | 소문자 주소 |
| 전화번호 | `010-1234-5678`, `021234567`, `+82 10-1234-5678`, `0082 31 123 4567` | `010-1234-5678`, `02-123-4567`, `031-123-4567` |
| 날짜 | `2025-01-31`, `2025.1.31`, `2025년 1월 31일` | ISO `2025-01-31` |
| 금액 | `12,000원`, `3천5백만원`, `$49.9` | 통화 변환 없는 정수 `12000`, `35000000`, `49` |
| URL | `https://example.com/a`, 대문자 호스트, 쿼리·fragment | 스킴·호스트를 소문자로 만들고 쿼리·fragment 보존 |

대표 URL 패턴은 `(?<![A-Za-z0-9_])https?://호스트(?::\d+)?(?:[/?#]나머지)?` 구조다. `https?`의 `?`는 `s`가 0회 또는 1회, `*`는 앞 요소가 0회 이상, `+`는 1회 이상, `{m,n}`은 m회 이상 n회 이하임을 뜻한다. `(?:...)`는 캡처 번호를 만들지 않는 그룹이고 `(?<!...)`는 앞 문자가 식별자가 아닌지 검사한다. 수량자를 넓게 쓰면 문장부호까지 과도하게 소비할 수 있어 호스트·경로의 허용 문자와 끝 경계를 따로 제한한다. 전화·날짜·금액도 숫자 앞뒤 경계와 캡처 그룹을 분리해 일반 수량, URL 속 숫자, 더 긴 번호의 일부를 배제한다. 실제 패턴과 경계별 설명은 [추출 설계](docs/extraction.md)에 있다.

전화는 `010 1234 5678 → 010-1234-5678`, 국제 표기는 `+82 10-1234-5678 → 010-1234-5678`, 금액은 `3천5백만원 → 35000000`으로 정규화한다. 같은 국내 번호와 국제 번호가 함께 나오면 표준형 기준으로 중복을 제거한다.

새 패턴은 `src/extractor.py`의 대상별 정규식과 정규화 함수에 추가한다. 넓은 패턴보다 구체적인 표기를 먼저 적용하고, 원문 구간을 기준으로 중복을 제거한다. 변경 순서는 ① 정상·경계·오탐 fixture 추가, ② 단위·CLI 회귀 정의, ③ CI 검증, ④ 측정 원자료와 보고서 갱신이다. 국제 전화 fixture는 `data/international_phone_test_cases.json`, 기존 고정 평가는 `data/ie_test_cases.json`에 둔다.

## 필수 감성 분석

`src.sentiment.analyze_sentiment(text, lexicon=None, use_rules=True)`는 토큰, 감성 근거, 기본 점수, 가중치, 적용 규칙, 최종 점수와 라벨을 반환한다. 사전은 `data/sentiment_lexicon.json`의 일반 어휘 207개와 고객 문의·리뷰 도메인 어휘 36개로 구성했다. 기존 프로젝트 목록을 직접 검토·보완했으며 외부 사전을 복제하지 않았다.

각 감성 토큰 `i`의 기본 점수를 `s_i`, 규칙 가중치를 `w_i`라 하면 최종 점수는 `S = Σ(s_i × w_i)`다. 판정은 `S > 0.5`면 `positive`, `S < -0.5`면 `negative`, 그 사이는 `neutral`이다. 한 문장에 긍정과 부정이 함께 있으면 합산하므로 상쇄된 혼합 감성도 `neutral`이 될 수 있다.

```json
{
  "tokens": ["정말", "좋다"],
  "detected_sentiments": [{"token": "좋다", "base_score": 1.0, "weight": 1.5, "weighted_score": 1.5, "rules": ["intensifier:정말"]}],
  "final_score": 1.5,
  "label": "positive"
}
```

규칙은 다음 순서로 적용한다.

1. 등록된 이중부정 구문을 긴 구문부터 먼저 매칭하고 해당 토큰을 한 번만 소비한다. `나쁘지 않다`처럼 의미가 굳은 구문은 등록 점수를 사용한다.
2. 같은 절에서 감성어 앞 최대 세 토큰의 부정어와 강조어를 찾는다. 부정은 `× -1`, 강조는 한 번만 `× 1.5`를 적용한다.
3. 감성어 뒤의 `않다`, `없다`, `아니다` 계열 부정 보조 용언을 확인한다.
4. 쉼표·마침표·줄바꿈·접속 표현을 넘어서 수식어를 전파하지 않는다. 명사나 다른 감성어를 만나도 탐색을 멈춘다.

예를 들어 `정말 좋다`는 강조 1.5배, `정말 안 좋다`는 같은 절의 부정까지 적용해 -1.5다. `좋다. 안 비싸다`에서는 마침표를 넘어 `안`이 `좋다`에 적용되지 않는다. 강조어별 차등 효과를 뒷받침할 독립 실험이 없으므로 현재 목록은 모두 1.5배를 한 번만 적용한다.

새 감성어는 일반/도메인 사전 중 의미에 맞는 한 곳에 기본형과 점수를 추가한다. 활용형은 `surface_forms`, 부정어·강조어·이중부정은 각각 전용 목록에 추가한다. 구체적인 이중부정이 일반 단어 규칙보다 우선하며, 변경 시 `data/sentiment_test_cases.json`에 긍정·부정·중립 및 규칙 경계 사례를 함께 추가한다. 구축 기준과 라이선스 설명은 [감성 설계](docs/sentiment.md)에 있다.

이중부정 회귀 묶음은 ① 기본 구문, ② 활용형, ③ 강조어 결합, ④ 절 경계, ⑤ 모양은 비슷하지만 이중부정이 아닌 음성 사례를 포함한다. 새 구문은 이 묶음이 모두 정의된 뒤 사전에 추가한다.

## 모듈 구조와 인터페이스

| 파일 | 공개 역할 | 분리 이유 |
|---|---|---|
| `src/extractor.py` | 추출·정규화 | 패턴 경계와 필드별 정규화를 독립 회귀 검증 |
| `src/sentiment.py` | 사전 로드·토큰화·점수 계산 | 사전과 부정·강조 규칙을 정보 추출과 독립 확장 |
| `src/evaluator.py` | Precision·Recall·Accuracy·Macro F1 | 예측 로직과 지표 계산을 분리하고 0인 분모 방어 |
| `main.py` | JSON/텍스트 CLI와 평가 명령 | 라이브러리 함수를 변경하지 않고 실행 흐름 조합 |

모듈은 JSON 호환 `dict`/`list`를 경계로 연결된다. 이 구조는 정규식, 점수 규칙, 평가 계산의 변경 원인을 분리하고 각 계층을 단위 테스트하기 위한 것이다.

```json
{
  "extract_information": {"emails": ["str"], "phones": ["str"], "dates": ["YYYY-MM-DD"], "amounts": [0], "urls": ["str"]},
  "analyze_sentiment": {"tokens": ["str"], "detected_sentiments": [{"token": "str", "base_score": 1.0, "weight": 1.0}], "final_score": 0.0, "label": "neutral"},
  "evaluation": {"pattern": {"precision": 1.0, "recall": 1.0}}
}
```

## 평가 데이터와 지표

정보 추출은 고정 50문장으로 다섯 패턴을 각각 10문장 이상 평가한다. 감성은 중복 없는 고정 160문장(긍정 55·부정 70·중립 35)을 사용하며 예측을 본 뒤 정답 라벨을 바꾸지 않았다.

- Precision = `TP / (TP + FP)`: 추출한 결과가 얼마나 정확한지 나타낸다. 경계를 좁히면 오탐이 줄어 Precision은 오르기 쉽지만 실제 표기를 놓쳐 Recall이 낮아질 수 있다.
- Recall = `TP / (TP + FN)`: 정답을 얼마나 빠짐없이 찾았는지 나타낸다. 패턴을 넓히면 Recall은 오르기 쉽지만 오탐으로 Precision이 낮아질 수 있다.
- Accuracy = `정답 문장 수 / 전체 문장 수`다.
- Macro F1은 positive·negative·neutral 각 클래스의 F1을 같은 비중으로 평균한다. 소수 클래스의 실패도 드러내며 모든 지표는 분모가 0이면 0으로 처리한다.

개인정보 탐지처럼 미탐 비용이 큰 흐름은 Recall을 우선하고, 자동 치환처럼 정상 텍스트를 바꾸는 비용이 큰 흐름은 Precision을 우선한다. 두 지표의 목표는 사용 위치의 오류 비용으로 정한다.

| 정보 추출 | Precision | Recall |
|---|---:|---:|
| 이메일 | 1.000000 | 1.000000 |
| 전화 | 1.000000 | 1.000000 |
| 날짜 | 1.000000 | 1.000000 |
| 금액 | 1.000000 | 1.000000 |
| URL | 1.000000 | 1.000000 |

| 같은 160문장 감성 비교 | Accuracy | Macro F1 |
|---|---:|---:|
| 개선 사전, 규칙 끔 | 0.750000 | 0.759672 |
| 개선 사전, 규칙 켬 | 0.843750 | 0.841337 |

규칙 효과는 같은 사전과 같은 160문장에서 마지막 두 행을 비교한 값이다. 전체 실행 조건, 해시와 문장별 결과는 [최종 보고서](docs/report.md)와 [측정 원자료](docs/results/final.json)에 보존한다.

## 실패 사례와 규칙의 한계

정보 추출의 변경 전 실제 실패 5건은 다음과 같고 수정 후 고정 50문장의 불일치는 22건에서 0건으로 줄었다.

| 입력 | 기대 결과 | 기존 실제 결과 | 원인 |
|---|---|---|---|
| `1억 2천만원` | `120000000` | 부분 금액만 추출 | 복합 한글 단위 합산 부재 |
| `3천5백만원` | `35000000` | 부분 금액만 추출 | 연속 단위 조합 부재 |
| `참가자 100명` | 금액 없음 | 숫자를 금액으로 오탐 | 통화 단서 없는 숫자 허용 |
| `https://example.com?q=1` | 쿼리 포함 URL | 도메인까지만 추출 | 도메인 직후 쿼리 경계 누락 |
| `02-123-4567` | 전체 전화번호 | 일부 또는 미추출 | 지역번호 가변 길이 경계 부족 |

감성 규칙 적용 후 기존 160문장의 오분류 25건은 사전 누락 1건, 반어 10건, 인용 6건, 문맥 의존 8건이다. 대표 10건 이상의 유형은 다음과 같다.

| 유형 | 대표 입력·기대 | 규칙 한계 |
|---|---|---|
| 사전 누락(1) | `태도가 공평하다` → positive | `공평하다` 미등록 |
| 반어(10) | `배송이 늦었는데 참 빠르네요` → negative | 표면의 긍정어를 실제 칭찬으로 해석 |
| 반어(10) | `고장이 났는데 품질이 훌륭하네요` → negative | 사건과 뒤 감탄의 관계 미해석 |
| 인용(6) | `상담원이 "좋다"고 말했다` → neutral | 화자와 인용 주체를 구분하지 않음 |
| 인용(6) | `후기에 "최고"라고 쓰여 있다` → neutral | 보고된 의견을 작성자 의견으로 계산 |
| 문맥(8) | `세 시간을 기다렸다` → negative | 시간·상황의 함축 감성 미등록 |
| 문맥(8) | `같은 질문으로 되돌아왔다` → negative | 반복 실패의 의미를 이해하지 못함 |
| 문맥(8) | `빈손으로 돌아왔다` → negative | 결과 상태의 부정 함의 미지원 |
| 혼합 | 긍정·부정 근거가 같은 크기 | 합산 결과가 중립이지만 측면별 차이는 잃음 |
| 이중부정 | 등록되지 않은 새로운 표현 | 고정 구문 밖의 통사 범위를 일반화하지 못함 |

정규식은 설명 가능하고 작은 고정 형식에서 빠르지만, 표기가 늘수록 패턴 우선순위·중복·경계 회귀 테스트 비용이 커진다. 사전 규칙도 결과 근거를 추적하기 쉽지만 신조어, 띄어쓰기, 대명사, 반어, 인용과 긴 문맥을 일반화하기 어렵다. 형식과 오류 비용이 명확하고 데이터가 적으면 규칙 기반이 적합하다. 표현 다양성이 크고 충분한 대표 학습·검증 자료와 운영 모니터링을 확보할 수 있으면 ML이 적합하다.

하이브리드 구성에서는 개인정보·날짜·금액처럼 계약이 고정된 값은 규칙 결과를 확정한다. 규칙 근거가 없거나 미등록 문맥인 감성만 ML 후보로 넘기고, 두 결과가 충돌하면 자동 조치에서는 보수적인 규칙 결과 또는 사람 검토를 우선한다. 라우팅 여부와 양쪽 근거를 함께 기록한다.

## 테스트와 CI

단위 테스트는 대상별 정규화, 정규식 경계, 부정·강조·이중부정, 지표의 0인 분모를 검증한다. 통합 테스트는 CLI JSON 계약과 전체 평가 실행을 확인하고, 실제 실패 사례는 회귀 테스트로 고정한다. `.github/workflows/ci.yml`은 push와 pull request에서 Python 3.11 환경을 구성하고 전체 unittest를 실행한다. 기능 완료는 해당 커밋의 GitHub Actions 성공으로 판정한다. 과거 단계별 테스트 개수는 구현 시점 기록이므로 현재 총개수로 사용하지 않으며, 최신 검증 결과는 해당 Actions 실행을 기준으로 한다.

중요 경로 체크리스트는 5종 추출·정규화, 국제/국내 전화 중복과 오탐 경계, 부정·강조·이중부정, 지표의 0 분모, CLI JSON 계약이다. 커버리지 백분율은 도구와 기준선을 실제 도입·측정한 뒤 정하며 측정 전 목표 달성을 주장하지 않는다.

```shell
uv run --python .venv python -B -X utf8 -m unittest discover -s tests -v
```

## 보너스 구현

필수 미션과 별도로 다음 선택 기능을 구현했다.

- 개인정보·주소 마스킹: `--mask`. 전화·주민번호·카드·국내 주소 표시를 가리며 주소는 시·도와 시·군·구까지만 남긴다.
- TF-IDF 비교: `--compare-sentiment`. 별도 합성 학습 1008문장에서 학습 크기 10·100·1000과 5개 시드를 비교한다.
- Aspect 감성: `--aspect`, `--evaluate-aspect`. 음식·가격·서비스·배송·품질을 측면별로 판정한다.
- 반어·인용·문맥 분석: `--contextual`, `--evaluate-contextual`. 명시적 인용 제외, 최종 의사·결과, 제한된 반어 단서를 처리한다.

```shell
uv run --python .venv python -B -X utf8 main.py --text "주소 서울 강남구 테헤란로 123, 연락처 02-123-4567" --mask
uv run --python .venv python -B -X utf8 main.py --text "음식은 맛있는데 가격이 비싸요" --aspect
uv run --python .venv python -B -X utf8 main.py --text "배송이 늦었는데 참 빠르네요" --contextual
```

`음식은 맛있는데 가격이 비싸다`는 문장 전체 합산에서 +1 + (-1) = 0이므로 `neutral`이다. Aspect 출력은 상쇄 전 근거를 보존한다.

```json
{
  "overall": {"score": 0.0, "label": "neutral"},
  "aspects": [
    {"aspect": "food", "score": 1.0, "label": "positive"},
    {"aspect": "price", "score": -1.0, "label": "negative"}
  ]
}
```

보너스 규칙 역시 자체 작성 개발 자료에 맞춘 관측값이며 독립 블라인드 평가의 일반화 성능은 확인하지 않았다. 국제 주소, 한국 국가번호 이외의 국제 전화, 한글 숫자 전체, 음수 금액, 환율 변환은 지원 범위 밖이다.
