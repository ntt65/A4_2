## 5. 토큰 실측과 캐시의 의미

VS Code 주담당의 로컬 세션 로그에서 `token_usage_record`를 모델 응답 ID별로 집계했다. 비캐시 입력은 `input_tokens - cached_input_tokens`로 계산했다. 출력에는 추론 토큰이 포함된다. 아래 수치는 보조 에이전트를 포함한 전체 비용을 나타내지 않는다.

| 구간 | 경과 시간 | 모델 호출 | 캐시 입력 | 비캐시 입력 | 출력·추론 |
| --- | ---: | ---: | ---: | ---: | ---: |
| #7 승인부터 다음 요청까지 | 14분 46초 | 29회 | 8,115,584 | 281,022 | 35,314 |
| 미션 코드·보고서 구현 | 26분 39초 | 51회 | 9,313,152 | 108,701 | 67,669 |

- #7의 8,431,920토큰 중 8,115,584개는 캐시 입력이었다. 비캐시 입력과 출력을 더하면 316,336개다. 지인의 미션 전체 30만 토큰과 비교하려면 집계 기준과 에이전트 포함 범위를 확인해야 한다. 캐시도 할인 요율의 사용량이다. 원시 토큰 합계, 구매 크레딧, 구독 한도를 각각 확인한다. [Codex 토큰 요율](https://learn.chatgpt.com/docs/pricing#token-rates)

## 6. 토큰 절감과 로컬 SQLite 설계안

1. CI나 Git 상태 대기는 로컬 명령에 맡긴다. 마지막 상태를 기억해 완료, 실패, 의미 있는 변경만 전달한다. 단일 프로젝트에서는 작은 JSON 상태 파일을 사용할 수 있다. Redis는 여러 작업자의 공유 상태나 결과 캐시가 필요한 경우의 선택지다. 로컬 결과 캐시는 모델 호출을 줄여 주고, 모델 내부의 KV 캐시는 OpenAI 서버에서 동작한다. [호출과 입력 최적화](https://developers.openai.com/api/docs/guides/latency-optimization)
2. 독립 조회를 묶고 `rg`로 관련 파일·줄만 찾아 읽는다. 테스트 출력은 성공 요약이나 필요한 실패 부분만 전달한다. 독립 작업은 새 채팅에서 해당 이슈와 짧은 인계로 시작한다. 같은 과제를 이어가는 긴 채팅은 `/compact`를 사용할 수 있다. [Codex의 긴 채팅 운영](https://learn.chatgpt.com/docs/learn/best-practices#organize-long-running-chats) · [기존 토큰 절감 인계문](../CACHE_HANDOFF.md)
3. 탐색과 인계의 반복 비용이 확인되면 `index.md`와 `reverse_index.md` 역할을 로컬 SQLite에서 구현한다. 파일 경로에서 심벌·기능을 찾는 조회와, 기능·심벌에서 구현·테스트·문서를 찾는 조회에 같은 데이터를 사용한다. Python 함수 위치는 AST로 수집하고 기능과 테스트·문서 관계는 작은 목록으로 관리한다. 브랜치 전환이나 파일 변경 시 위치를 갱신한다. [Python SQLite 문서](https://docs.python.org/3/library/sqlite3.html)
4. 같은 DB에 이슈·커밋별 결정, 승인 범위, 검증 결과, 남은 작업, 원문 채팅·메시지 ID를 기록한다. 원문은 기존 로컬 로그에 두고 필요할 때만 참조한다. `context "#3"` 또는 `lookup "금액 추출"` 한 번으로 승인 범위, 검증 상태, 코드·테스트·문서 위치를 몇 줄만 반환하도록 설계한다.
5. 같은 읽기 전용 검증을 현재 긴 채팅과 짧은 새 채팅에서 비교한다. 그 다음 동일 작업을 `rg` 조회와 SQLite 조회로 비교한다. 모델·추론 강도와 검증 범위를 고정하고 결과 일치, 호출 수, 캐시·비캐시 입력, 출력, 경과 시간을 기록한다. 추론 강도는 별도로 비교한다. SQLite·Redis·권한 제한은 아직 구현하거나 절감률을 측정하지 않은 제안이다.

## 7. 이슈·커밋 단위 채팅과 접근 제한

- 이슈 하나를 채팅 하나에서 승인·구현·검증·커밋까지 관리하는 방안에서 시작했다. 이슈 내부에 독립적으로 검증할 수 있는 커밋이 있으면 작업 채팅도 나눌 수 있다. 주담당은 기준 커밋 SHA, 승인 범위, 담당 파일, 의존 계약, 재현 사례, 완료 조건만 넘기고 결과를 통합한다.
- 금액과 URL처럼 같은 `extractor.py`를 수정하는 작업은 순차로 통합한다. 파일 소유권이 분리된 작업은 별도 브랜치·worktree에서 병행할 수 있다. 작업자는 필요한 검증을 수행하고 주담당이 전체 회귀와 커밋·PR 범위를 확인한다.
- 채팅을 나누면 대화 문맥이 분리된다. worktree는 파일 변경을 격리한다. 작업자가 전체 저장소나 다른 채팅을 실제로 읽지 못하게 하려면, 필요한 파일과 테스트 의존성만 제공하는 샌드박스와 파일 읽기 권한을 설정한다. GitHub·채팅 기록 도구의 조회 범위도 같이 제한한다. [Codex 프로젝트와 채팅](https://learn.chatgpt.com/docs/projects) · [Codex 파일시스템 권한](https://learn.chatgpt.com/docs/permissions)
