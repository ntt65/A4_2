## 주소 보너스 구현과 검증

- 기준은 HEAD `6c0fc70` 이후 이 문서와 함께 커밋하는 주소 구현 작업 트리다. 기존 필수 기능의 측정 기준과 원자료는 위 실행 조건에 기록했다.
- 시·도부터 표기한 국내 도로명·지번 주소와 숫자 동·층·호를 추출하고 정규화한다. Python API는 `extract_addresses(text)` 또는 `extract_information(text, include_addresses=True)`로 호출하며 CLI의 `addresses` 키로도 반환한다.
- `--mask`는 시·도·시·군·구까지만 남겨 주소를 가린다. 예를 들어 `경기도 성남시 분당구 판교역로 166 101동 1203호`는 `경기도 성남시 분당구 ***`로 표시한다.
- Windows-10-10.0.26200-SP0·CPython 3.11.4에서 2026-11-15 전체 unittest **42개가 2.346초에 통과**했다. 기존 추출 50문장의 다섯 패턴 Precision·Recall은 각각 1.000000 / 1.000000이다. 기존 감성 160문장의 규칙 전 Accuracy/Macro F1은 0.750000 / 0.759672, 규칙 후는 0.843750 / 0.841337이다.
- 새 테스트 7개에 정상 주소 표기 12개, 조사·복수 주소·중복 제거·URL/식별자/숫자 경계와 상세주소 마스킹을 포함했다. 주소 라벨 평가 fixture에서는 실제 오탐·미탐 집계와 주소 라벨이 없는 행 처리를 검증했다. 지원 형식과 수정한 쉼표 상세주소 결함은 [추출 문서](extraction.md#주소-추출마스킹)에 기록했다.

기존 소스는 `git show f19be4a:src/sentiment.py`로 읽어 메모리에서 실행하고 보존한 기존 사전을 명시적으로 전달했다. 모든 행에서 같은 160문장·라벨을 사용했다. 규칙 자체의 효과는 개선 사전과 표면형 처리를 고정한 마지막 두 행에서 **75.0% → 84.375%**다. 기존/개선 전체 비교에는 사전과 코드의 효과가 함께 들어 있다.

감성 데이터는 긍정 55 / 부정 70 / 중립 35개이며 고유 문장은 160개다. 최종 오분류는 **25건**이다. 사전 누락 1건, 반어 10건, 인용 6건, 문맥 8건을 [입력 → 기대 vs 실제 → 원인](sentiment.md) 형식으로 전부 기록했다. 정답 라벨을 예측에 맞춰 바꾸거나 실패 문장만 겨냥하는 규칙을 추가하지 않았다.

## 한계와 후속 개선

자체 작성한 개발 평가 자료이므로 독립적인 일반화 성능 검증은 아니다. 사전·규칙으로 반어, 인용의 화자, 문맥의 최종 의사, 측면별 감성을 모두 해석할 수 없다. 형태소 분석 없는 제한된 활용 규칙은 미등록 활용과 신조어를 놓친다. 정보 추출은 한글 숫자·국제 전화·국제화 주소·음수·환율 변환을 지원하지 않는다. 숫자 단위와 수량, URL 문장부호의 의미도 항상 판별하지 못한다.

외부 사전을 다운로드하지 않았다. 기존 출처 주장 중 확인 근거 없는 국립국어원 설명을 제거하고 자체 구축·보완 내역을 명시했다. 출처·라이선스 상태와 원본 SHA-256은 [감성 문서](sentiment.md)에 있다. 기존 감성 자료는 바이트 그대로 `data/archive/`에 보존했다.

후속 개선은 독립 평가자와 검증셋 확보, 새로운 데이터에서의 표면형·부정 범위 검증, 선택 과제인 통계 모델 비교·Aspect 분류 순서가 적절하다.
