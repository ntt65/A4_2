# 정보 추출 및 마스킹

## 구현과 정규화

- 이메일: 점·별칭·서브도메인을 처리하고 소문자로 정규화한다. ASCII 주소 내부의 부분 매칭을 막되 한국어 조사는 허용한다.
- 전화: 서울 02 및 3자리 국내 번호의 하이픈·점·공백·무구분 표기를 하이픈으로 통일한다. 긴 숫자와 ASCII 식별자 내부는 제외한다.
- 날짜: 한글 및 동일한 `/`, `-`, `.` 구분자의 2자리/4자리 연도를 처리한다. 실제 달력 날짜를 검사하고 ISO 8601로 반환한다. 2자리 연도는 00~49를 2000년대, 50~99를 1900년대로 해석한다.
- 금액: `$`, `원`, `억`·`만` 계열의 명시적인 표기를 처리하고 한 문장의 복수 금액을 찾는다. 천·백·십을 모아 만·억 단위 앞에서 묶으므로 `1억 2천만원`은 120000000, `3천5백만원`은 35000000이다. 숫자와 단위를 Decimal로 계산하고 정수로 변환한다. `$49.9`는 기존 정답 데이터와 같이 49로 소수 부분을 버린다.
- 일반 숫자, 날짜·전화의 숫자, 잘못된 천 단위 쉼표, 명·개 등의 수량 표기는 금액에서 제외한다. URL 내부의 금액 모양 문자열도 제외한다.
- URL: 대소문자 스킴·호스트, 포트, 슬래시 없는 쿼리, 경로 및 fragment를 처리한다. 스킴·호스트만 소문자로 만들며 경로·쿼리·fragment를 보존한다. 문장 마침표와 불균형 닫는 괄호는 제거한다.

`extract_information(text)`의 반환 키는 `emails`, `phones`, `dates`, `amounts`, `urls`다. 각 값은 정렬된 중복 제거 목록이며 금액은 정수, 나머지는 문자열이다.

`--mask`는 원문에서 먼저 정보를 추출한 뒤 출력용 추출값과 분석 문장을 마스킹한다. 예를 들어 전화 목록은 빈 목록 대신 `["02-***-4567"]`을 표시한다. 주민번호·16자리 카드·전화번호 모양을 처리하며 실제 유효성이나 카드 체크섬 판정은 수행하지 않는다.

## 측정

- 변경 전 기준: `f19be4a`; 원자료는 [baseline.json](results/baseline.json).
- 변경 후 기준: 이 문서와 함께 커밋한 #3 구현 작업 트리. 기존 IE 정답 JSON 50문장은 수정하지 않았다.
- 환경: Windows, Python 3.11.4, uv 0.13.7, 2026-11-15.
- 명령: `uv --no-cache run --python .venv python -B -X utf8 main.py --evaluate-ie`.
- 회귀 검증: `uv --no-cache run --python .venv python -B -X utf8 -m unittest discover -s tests -v` (기존 8건 + 신규 14건 = 22건 통과).

문장 전체의 정답과 다른 경우는 22 / 50에서 0 / 50으로 줄었다. 각 패턴 10문장의 기존 데이터 외에 패턴별 3가지 이상 표기, 잘못된 날짜·숫자 경계·복수/복합 금액·URL 문장부호·마스킹 순서를 회귀 검증한다.

통합 전 독립 검토에서 발견한 `3천5백만원`의 단위 합산 오류도 수정했다. `1억2천3백만원` 및 `1억2천3백4십5만원`을 함께 회귀 검증했으며, 추출 테스트 7건을 다시 실행해 통과했다.

## 실제 수정 전 실패 5건과 수정 후 결과

1. **전화 숫자 오탐**: `연락처는 010-1234-5678 입니다.` -> 기대 금액 `[]` vs 수정 전 `[10]` -> 통화 단위가 선택 사항이어서 전화 일부를 금액으로 매칭 -> 수정 후 `[]`.
2. **날짜 숫자 오탐**: `납기일: 2024/01/15` -> 기대 금액 `[]` vs 수정 전 `[1, 15]` -> 날짜의 구분자 사이 숫자를 일반 금액 패턴으로 매칭 -> 수정 후 `[]`.
3. **긴 숫자 금액 미탐**: `결제금액 50000원` -> 기대 `[50000]` vs 수정 전 `[]` -> 쉼표 없는 숫자가 1~3자리로 제한됨 -> 수정 후 `[50000]`.
4. **복합 단위 미탐**: `대형 계약 1억 2천만원` -> 기대 `[120000000]` vs 수정 전 `[]` -> 모든 그룹이 선택 사항인 패턴의 첫 빈 매칭만 사용함 -> 수정 후 `[120000000]`.
5. **쿼리 손실과 숫자 오탐**: `쿼리 포함 http://service.kr?a=1&b=2` -> 기대 URL `http://service.kr?a=1&b=2`, 금액 `[]` vs 수정 전 URL `http://service.kr`, 금액 `[1, 2]` -> 경로 `/` 뒤에만 쿼리를 허용하고 쿼리 숫자도 금액으로 매칭함 -> 수정 후 기대값과 일치.

## 범위와 한계

- 이 점수는 직접 작성한 50문장과 회귀 사례의 결과이며 모든 자연어 표현에 대한 정확도를 뜻하지 않는다.
- `억`·`만` 단위는 문맥에 따라 수량과 혼동할 수 있다. 명시적인 수량 접미사는 제외하지만 의미 분석은 수행하지 않는다.
- 숫자를 한글로 쓴 연락처, 음수·환율 변환, 국제 전화, 국제화 이메일/도메인 전체 문법은 지원 범위 밖이다.
- 문장부호와 URL에 포함된 같은 문자는 문맥만으로 항상 구분할 수 없다.
